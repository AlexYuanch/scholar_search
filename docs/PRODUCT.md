# 产品说明

## 产品定位

ScholarSearch 面向教师、学生、科研团队与高校科研管理人员，定位为持续在线的科研助手，而不是论文搜索页。系统围绕学者、论文、机构、研究方向、合作关系和时间线整理公开资料，帮助用户看懂一位学者、比较重点同行、发现潜在合作者，并持续追踪研究进展。

## 当前功能

1. **检索与学者选择**：中文名补充两种拼音顺序，同时保留英文名和直接拼音搜索。除 OpenAlex 作者档案外，系统会从精确匹配论文署名反向提取作者、机构、DOI 与合作者；署名没有 Author ID 时仍生成“由论文发现，待确认”候选，并以论文作为画像锚点。候选页只展示用户可理解的机构、ORCID、研究方向、论文、引用、h-index 和最近发表年份，并支持机构、方向、ORCID 与指标筛选；正式作者卡片只显示一个由连续两年或至少两篇论文支持的“主要论文关联机构”，其他机构默认收起为“往年论文曾关联的信息”；“归并信号”“独立档案指纹”等内部判定过程不进入主界面。
2. **多来源裁决画像**：分页获取 OpenAlex 作者与论文，以 DOI 查询 Crossref，读取无需密钥的 ORCID 公共论文记录，并用 DBLP 核对计算机领域作者与已有论文；按 DOI 或题名年份匹配并保留字段来源、差异和待核实状态。Google Scholar 仅在配置 SerpApi 后核对已有论文，不按姓名扩张画像论文集。OpenAlex 机构历史和论文署名原文只保留为内部身份核验证据，不在概览重复展示。
3. **全量论文**：画像 JSON 保持轻量，论文列表从 PostgreSQL 游标分页读取；研究方向时间线标签可跳到论文区，并按年份和方向筛选对应论文。
4. **稳定合作图**：节点以 OpenAlex ID 为主键；同名合作者显示机构或短 ID；图谱高度随浏览器视口和详情栏宽度自动调整，低饱和合作强度色阶跟随当前主题，并提供悬停、恢复视图和全屏操作；合作者姓名和节点先打开详情，只有用户点击“查询画像”才切换，连线继续打开共同论文。
5. **质量保护**：分页不完整、数量明显不一致、论文异常下降或工作流报错时不发布新版。
6. **当前数据与画像生成**：首次画像先进入持久任务队列并写入查询历史，由 worker 获取 OpenAlex 当前数据、执行 Crossref/ORCID 核验和 Agent 分析；当前页面以身份核验、成果汇总、轨迹分析和依据复核四个阶段解释处理流程。已有成功画像立即展示，超过刷新阈值或点击“更新资料”后同样异步重跑，失败不影响最近成功版本。
7. **研究追踪**：追踪学者每天检查，近 30 天访问学者每 7 天检查；新画像相对用户上次查看基线计算新增论文、引用和可检测的研究方向变化，查看最新版后清除提醒；任务最多重试 3 次。面板支持立即检查、重试、查看画像和停止追踪。
8. **匿名首页、登录与私有数据**：匿名用户先浏览简洁产品首页、新手指南、匿名标题的完整查询过程和能力边界，右上角可登录；案例以浏览器原生高清组件演示身份确认、后台生成、合作图节点/连线、历史和追踪，内容随滚动淡入淡出并尊重系统的减少动态效果设置。提交搜索时才弹出可关闭的登录/注册框，成功后自动继续原搜索。查询、画像、论文、历史和研究追踪仍只对登录用户开放。
9. **任务状态与完成提醒**：数据库排队、更新、失败和发布版本变化后，前端通过 SSE 与查询历史轮询同步状态；首次画像完成后即使用户已进入首页或其他功能，也在右下角提醒并提供直接打开入口。
10. **请求生命周期**：主画像生成由持久 worker 任务承载，不随 React 组件卸载而取消；搜索、缓存读取、全部论文和实时换版等浏览器请求仍在学者切换时取消，避免旧响应覆盖新选择。兼容的流式画像接口继续用于学者对比。
11. **一致跳转**：从候选列表、合作姓名/节点、查询历史或研究追踪查看画像时，搜索框同步显示当前学者姓名；画像标题可打开对应 OpenAlex 主页。
12. **响应式界面与视觉语言**：全站采用暖黑/米白双主题，以及青绿、翠绿、梅紫和暖橙四套可选强调色；主题选择即时联动按钮、焦点、统计图表和合作图色阶。匿名首页突出“从一位学者读懂一条研究脉络”，插画随明暗主题切换并以轻量轨道、浮动和渐入动画增强反馈。英文界面使用稳定系统字体与独立字号/换行规则。顶部“首页”和管理员“系统概况”是一级内容导航，圆形用户头像位于最右侧；个人设置使用头像下方的紧凑下拉面板并按“外观与昵称 / 账户安全”分栏，中小屏限制在动态视口内滚动。文章详情、查询历史和研究追踪同样不会遮挡、裁切或产生横向溢出。
13. **学者对比**：从当前画像选择并确认第二位学者，重新获取对方当前数据，并列比较研究方向、研究时间线、代表作、论文与引用、影响力、合作者和近期变化；每个模块显示计算口径或事实依据，移动端纵向排列。
14. **近期研究变化**：以学者最近发表年份为基准，对比连续两个三年阶段的方向数量与占比；变化 Agent 结合方向说明和两个窗口的真实代表论文，最多输出四条关于研究问题、方法或应用变化的洞察，不允许只复述数量。
15. **公开服务保护**：搜索与画像生成分别按账号和来源 IP 计数；同名搜索共享 PostgreSQL 结果与身份指纹缓存，并发冷请求合并为一个 worker 任务；上游剩余额度达到保护线后只提供旧缓存或已发布学者的本地结果。
16. **自动备份**：Compose 启动后立即生成 PostgreSQL 备份，之后按配置周期执行并清理过期文件。
17. **数据说明**：概览以简洁卡片展示当前收录、更新时间、来源和可能遗漏；Crossref 比例、冲突与分页细节折叠到“查看收录范围与使用说明”，不干扰核心研究内容。
18. **证据审查**：总结中的指标、方向、论文和合作依据必须能回溯到裁决后论文集；无法追溯的依据被拒绝，关键指标审查失败时阻止新版发布。
19. **细粒度方向**：优先使用 OpenAlex topics 与 keywords；标题短语只有在至少 3 篇论文重复且不超过 4 词时才可辅助候选。方向 Agent 仅接受 2–8 个词的规范领域名，与论文标题高度相似、过宽或无法追溯的输出必须升级或回退。
20. **身份一致性审查**：ORCID 命中论文优先形成主论文集；DOI、同题同年记录和稳定合作者建立强连接，机构只作为主簇选择的辅助证据，不能单独把不同研究簇串联。多个 ORCID 直接命中的跨方向簇可以共同保留；无强身份连接的冲突簇排除并提示画像可能不完整。
21. **画像五栏**：学者概览集中展示研究画像、研究方向、核心指标、近期变化、时间线和数据说明；学术成果展示确定性代表作及全部论文；合作关系展示核心合作者和关系图；研究脉络展示研究阶段、方向变化、方向延续、选题特征和问题—方法—贡献演进；同行与机构只展示跨学者和跨机构的关注对象。
22. **同行与机构**：从长期和近期研究主题发现可进一步了解的同行、合作对象与相关机构；候选必须完成既有动态研究图谱后才参与确定性分析。首屏只消费并展示前 20 位图谱就绪候选，超过 20 位时通过“查看更多同行”每次追加下一批 20 位，不重复或覆盖已展示结果；图谱未就绪的候选先展示姓名、发现主题和论文规模等基础信息。结果用于学习研究路线、跟进同行、核对合作可能和选题重合，不生成绝对排名，也不改变现有代表作、论文、合作网络或研究脉络。
23. **发现成本边界**：领域样本扩展由用户主动触发，最多保留 60 位候选、累计补全 20 位；首批补全 8 位，后续每批 4 位。发现次数不进入推荐分数，OpenAlex 调用继续使用平台 key，未配置平台 key 时才回退到发起用户的加密凭据，并沿用现有额度保护。
24. **多 Agent 学术分析**：方向、变化、总结和证据 Agent 均优先调用 LongCat-2.0；服务不可用或输出未通过结构/证据校验时，再按规划层级回退 DeepSeek Flash/Pro。协调 Agent 会根据当前学者的论文、合作、机构与时间证据动态创建代表作、潜在合作、机构研究交集和研究延续性 Worker，不再为所有学者固定执行同一组分析。
25. **评估与修订闭环**：证据审查不再只做拒绝或降级；审查意见会返回总结 Agent 修改，并重新进入审查，最多修订两轮。循环结束后仍由确定性证据门禁决定是否发布。模型、路由和降级状态留在审计数据中，普通用户只看到通过审查的研究画像、研究变化和专业分析结论；API key、完整提示词和原始模型响应不返回浏览器。
26. **错误恢复**：无结果、网络错误、超时、限流、登录失效和 worker 失败采用不同状态；可恢复错误提供重试，切换学者会取消旧的搜索或画像请求。
27. **OpenAlex 凭据隔离**：平台管理员在服务器 `.env` 配置免费 OpenAlex key，普通用户注册登录后直接查询；后端保留可选的个人 key 加密存储能力。无可用凭据时继续提供已发布画像和缓存结果，前端、日志和仓库不返回密钥。
28. **研究脉络**：底层围绕 Paper、Author、Institution、ResearchTopic、Collaboration 和 TimelineEvent 保存可增量更新的单学者图谱；用户界面不重复论文栏或合作关系，而是展示研究阶段、方向变化、方向活跃度、问题—方法—贡献演进和内部引用主线。新画像晚于图谱时按需增量更新，重建入口只在失败后出现。
29. **摘要约束的论文理解**：有 OpenAlex 摘要时仅抽取摘要原句作为问题、方法、贡献、方向关系和证据，并标记“基于摘要”；摘要缺失时字段为空，不通过标题或模型补写。
30. **管理员运营看板**：管理员查看当前在线、访问与搜索趋势、注册/活跃用户、热门学者、后台任务和近期异常；概览卡可原位展开明细。匿名访客不保存姓名或原始 IP，普通用户看不到入口且接口返回 `403`。`admin` 为受保护的超级管理员，可授予或撤销其他账号的只读管理员权限。
31. **代理故障恢复**：生产前端动态解析后端容器地址，后端增量重建或容器 IP 变化后不再因旧地址缓存导致 API 全部返回 502；容器健康状态同时覆盖前端静态资源和后端就绪接口。
32. **分析页签响应**：画像打开后在浏览器空闲时间预取研究脉络与同行机构；跨页签共享最近成功结果，切换时先展示已有内容并后台检查更新。排队状态按 3、5、10、20 秒退避轮询，页面隐藏时暂停请求；单个候选或无关学者的图谱更新不会清空当前学者缓存。

## 数据与隐私边界

- OpenAlex 仍是学者与论文发现来源；当作者实体缺失时，系统可从 OpenAlex 精确匹配论文署名创建保守的待确认候选，但不会仅因同名或同机构把论文自动合并。Crossref、公开 ORCID、DBLP 和可选 Google Scholar 只核验已有论文。
- 运维人员可用脱敏追踪工具复现一次完整画像工作流，逐节点查看输入摘要、输出摘要、模型回退和耗时；报告不保存密钥、完整提示词或模型原始响应，也不写入用户业务数据。
- DOI 相同的来源记录视为同一论文；无 DOI 记录不丢弃，也不在证据不足时强制合并。
- 引用数保持 OpenAlex 口径，不与 Crossref 计数求平均；来源冲突保留在核验报告中。
- 多个 OpenAlex 作者 ID 只有在姓名一致且具有共同论文，或机构、合作者、主题等多个独立信号达到保守比例阈值时才自动归并；不同 ORCID 默认保持独立，机构履历异常扩散的档案也不参与上下文自动归并。
- 论文作者署名字符串只能证明该论文记录中的机构关联，不能证明当前任职、学院/实验室成员关系、职称或培养阶段；上述身份字段不得由论文数量、h-index、主题、OpenAlex 机构字段或个人仓库说明推断。
- 身份归并不删除或修改 OpenAlex 原始档案；系统保留主 ID、已归并 ID 和被拒绝 ID，并在“数据核验”中显示归并数量。
- 论文身份审查采用准确优先策略：ORCID 命中是强锚点，主题相似度不能单独建立身份连接；无足够身份信号时明确降级而不是假装确定。
- 旧 SQLite 13 条缓存不迁移，自托管 PostgreSQL 从空库开始。
- 只保留最新成功画像和 30 天任务日志，不保存历史画像版本。
- 用户名为 2–64 位，可使用中英文、大小写字母、数字、内部空格和常用符号；登录与唯一性判断忽略字母大小写。
- 密码至少 8 位，使用带随机盐的 scrypt 摘要保存，数据库不保存明文密码。
- 浏览器仅持有高熵、`HttpOnly` 的不透明会话 Cookie；数据库只保存会话 token 的 SHA-256 摘要。
- 登录失败按用户名和 IP 限速；错误响应不区分用户不存在、密码错误或账号停用。
- 注册不依赖邮箱、短信或微信；同一来源 IP 每小时最多尝试注册 10 次，密码重置暂由服务器管理员处理。
- 服务端 OpenAlex key 只存在于服务器 `.env` 和容器环境，不写入数据库、`localStorage`、前端构建产物、API 响应或日志。未来个人 key 接口仍使用 Fernet 密文并按用户隔离。
- 默认 10 分钟内每账号最多搜索 30 次、生成画像 12 次；同一 IP 上限分别为 120 次和 60 次，可由部署环境调整。
- 默认搜索缓存 24 小时、空结果缓存 15 分钟、身份指纹缓存 30 天；搜索缓存、任务和上游额度状态全部持久化到 PostgreSQL，重启和多实例不会丢失或各自重复抓取。
- “可公开使用”不等于上游无限：热门/已缓存姓名不重复消耗 OpenAlex，未见过且本地没有真实学者记录的姓名仍受 OpenAlex 账户每日额度限制。
- 平台统一使用 OpenAlex 免费额度；达到保护线后停止新的上游调用并进行缓存降级，不自动购买或消耗付费额度。
- 图谱不上传或抓取 PDF，不访问付费墙；内容事实仍以 OpenAlex 公开元数据/摘要为主，Crossref、ORCID、DBLP 与可选 Google Scholar 仅提供交叉核对。
- 图谱更新只作用于当前学者；用户打开“研究图谱”栏后才按需创建首次或过期任务，普通画像访问不提前建图。普通任务使用 OpenAlex 免费计划支持的 `from_publication_date` 和 30 天重叠窗口读取近期发表记录；新鲜版本不重复调用上游，显式单学者重建只在上一轮失败后开放。两者均不触发全库重建；OpenAlex 不完整批次不写内容，Crossref 失败不抹掉以前成功的出版字段。
- 分析版本 2 的图谱只接收当前身份裁决后画像中的论文 ID；图谱同步不得把被排除论文重新关联到画像，也不得覆盖论文筛选所需的 `analysis_topics`。
- 首次图谱同步成功前不展示画像表中的旧论文、机构或关系；已有成功版本后的更新失败只改变任务状态，不改变图谱内容。无摘要记录不会逐条生成空洞的“摘要缺失”卡片，页面只用一条明确空态说明不生成论文理解。
- 研究图谱使用 PostgreSQL 关系表，不引入 Neo4j、向量数据库、多 Agent 图谱构建或复杂工作区。
- 学者智能只读取动态研究图谱的学者、论文、主题、机构、合作、引用和摘要理解关系，不复制学术事实；新增数据库表只保存按用户隔离的判断反馈。
- 引用数不直接等同于质量，论文数不进入影响力得分，方向相似不单独产生竞争判断，一次合作不产生长期合作推荐。图谱未成功、样本不足或关键特征不足时必须显示“无法可靠判断”。
- “领域北极星”在产品文案中表达为当前领域样本内的参考学者，不输出绝对“最好学者”；竞争结果始终使用“潜在”措辞，选题风格只描述问题、方法、系统、数据或应用倾向，不评价人格。

## 成功标准

- 匿名用户可访问产品首页、健康检查和会话检查；所有平台查询能力必须登录，搜索触发登录后自动续接。
- 不同用户的查询历史和研究追踪按 `user_id` 隔离。
- 平台 OpenAlex key 不得出现在 API 响应、日志、任务错误或前端资源中；查询用户无需接触该密钥。
- 每个用户的追踪基线独立保存；新论文或引用增量只相对该用户上次查看的画像计算，不能被其他用户查看行为清除。
- 学者超过 50 篇论文时仍可分页访问全部论文。
- 时间线方向标签必须打开对应年份和方向的真实数据库论文；清除筛选后恢复该学者全部论文。
- 同名同机构但缺少共同论文、合作者和主题证据的候选不得自动合并；拆分档案通过强证据归并后，画像必须联合获取其论文并统一中心作者身份。
- 研究方向前列应优先呈现可由论文标题、OpenAlex topics 或 keywords 回溯的具体问题与方法，宽泛学科词不能在存在充分细粒度证据时占据主要位置。
- 已有成功画像必须先返回，不允许为相同点击同步重跑完整工作流；过期画像和首次画像都通过 `refresh_jobs` 幂等排队，首次画像立即进入历史并允许用户离开当前页面。
- 学者对比必须明确两位 OpenAlex 实体，使用同一统计口径，并标明指标只用于理解差异而不是学术质量排名。
- 近期研究变化使用学者自身前后两个阶段的主题占比，不能把论文总量变化直接解释为方向升降，也不把主题变化解释为研究质量变化。
- 部分 OpenAlex 结果不能覆盖旧画像；完整成功更新才递增版本。
- 所有分析节点必须消费裁决后的统一论文集，最终总结只能使用证据审查通过的依据。
- 启用模型时，画像必须记录各 Agent 实际模型、路由层级、自动升级和降级结果；任何 Agent 输出缺少可追溯主题、未知证据 ID 或结构校验失败时必须升级或回退，不能直接发布。
- SSE 收到新版本后自动切换最新版。
- Web、worker、PostgreSQL 和前端可由 Docker Compose 启动，也可拆分部署到 ECS/RDS。
- Gitee 拉取后只需填写 `.env` 并运行受保护的部署脚本，无需修改应用源码；后续默认按 Git 变更增量更新前端或后端，环境和基础设施变化自动回退为完整构建。
- 生产环境允许公开注册和登录，但没有开发登录后门；无有效会话的查询请求统一返回 401。
- 已检查的 Ubuntu 24.04 阿里云 ECS 可由引导脚本自动安装 Docker、补充 Swap、生成随机数据库密码和完成首次部署。
- 手动“立即检查”必须只创建或复用 `refresh_jobs` 活跃任务；未登录或未追踪该学者不得排队，Web 进程不得同步运行完整工作流。
- 搜索任务与画像刷新任务继续保存 `requested_by_user_id` 用于历史和所有权审计；worker 优先使用服务端 OpenAlex key，个人 key 仅在服务端 key 未配置时作为兼容回退。
- DOI/OpenAlex ID 重复输入不得生成重复论文；作者—论文、作者—机构、作者—主题、合作、引用和时间线关系必须由数据库唯一键去重并记录来源/置信度。
- 图谱后台失败不得改变最近成功的论文、关系和摘要证据；重新执行相同批次后对象与关系数量保持稳定。
- 研究时间线必须稳定倒序；方向和合作统计必须在增量批次后按已保存关系重算，而不是把重叠窗口重复累计。
- 任何无摘要论文都不得出现问题、方法、贡献、方向关系或摘要证据；有摘要论文必须显示“基于摘要”。
- 同行与机构的每个推荐必须返回因人而异的可读结论、可追溯证据、依据充分度与局限；默认界面不展示综合指数或伪精确排名。所有推荐使用稳定次级排序，重复读取同一图谱不得改变顺序。
- 候选发现只能决定补全谁；OpenAlex 分组次数不得直接进入参考、同行、合作或潜在竞争评分。图谱未完成、同名身份未核验或只有单一相似方向的候选不得进入建议。
- 机构活动只表示所选主题和时间窗口内的论文分组；不得解释为机构质量、影响力、团队完整名册或实验室归属。
- 跨领域高引用学者不得因引用数进入当前领域参考列表；同名作者按 OpenAlex ID 保持独立；潜在合作者与潜在竞争者不得重叠。
- 代表作必须同时考虑领域相关度、时间/领域归一化影响、作者贡献角色、后续扩散和主题延续，不能退化为引用数降序。

## 上线前事项

- 单机 ECS 首次启动会创建 PostgreSQL 17、数据库所有者和受限的 `scholar_app` 账号；使用 RDS 时需单独准备对应角色。
- 配置正式域名、HTTPS、CORS 和安全 Cookie。
- 将 Web 与 worker 作为独立进程运行，配置日志、监控、重启策略和告警。
- 当前自动备份位于宿主机目录；仍需同步到独立介质，并完成至少一次恢复演练。
- 禁止公网访问数据库和后端内部端口；OpenAlex、可选凭据加密和 LLM key 均由部署环境注入。当前 HTTP 阶段不开放个人 key 设置，账号密码登录仍应尽快迁移到正式域名与 HTTPS。
