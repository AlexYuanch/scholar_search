# 同名学者候选排序与筛选设计

## 目标

改进姓名搜索后的候选确认流程，让用户更快判断“哪个候选人是我要找的学者”，同时避免把学术影响力误当成身份匹配度。

本次范围只覆盖候选人结果页，不改变学者画像生成、身份合并算法和画像数据模型。

## 当前问题

- `CandidateList` 直接按照 API 返回顺序渲染候选人。
- 后端当前返回机构、ORCID、论文数、引用数、h-index、身份置信度和身份依据，但没有显式的候选分组、排序解释或研究方向标签。
- OpenAlex 搜索底层按引用数排序，容易让高影响力但不一定匹配的学者优先出现。
- 用户无法快速筛选机构、ORCID、身份置信度或研究方向。

## 设计原则

1. 默认排序表示身份匹配可信度，不表示学术影响力。
2. 不隐藏候选人；筛选只改变展示结果，并显示各组数量。
3. 排序和分组必须可解释，用户能看到推荐原因。
4. 论文数、引用数和 h-index 只作为用户主动选择的次级排序。
5. 无研究方向数据时，研究方向筛选不显示为可用条件，而不是伪造标签。

## 用户流程

搜索完成后，结果页展示：

```text
找到 N 位候选人
高置信度  ·  可能匹配  ·  需要确认
```

默认选中“全部”和“推荐匹配”。用户可以：

- 点击身份分组筛选；
- 输入机构关键词；
- 选择“有 ORCID”；
- 输入研究方向关键词；
- 切换推荐匹配、论文数、引用数、h-index、最近发表年份排序。

候选卡展示候选人的主要机构、其他机构、ORCID、论文/引用/h-index、合并档案数，以及最多三条推荐理由。

## 数据契约

扩展 `Candidate`：

```ts
type CandidateIdentityGroup = "high" | "medium" | "review"
type CandidateSortReason = {
  code: string
  label: string
  value?: string | number
}

interface Candidate {
  identity_group: CandidateIdentityGroup
  identity_score: number
  match_reasons: CandidateSortReason[]
  latest_publication_year?: number | null
  research_topics?: string[]
}
```

`identity_score` 是身份证据强度的可解释排序值，不包含引用数、论文数和 h-index。分组规则：

- `high`：高置信度身份合并，或存在强身份依据；
- `medium`：存在部分交叉证据，但仍需要用户确认；
- `review`：独立档案、证据不足或存在身份风险。

第一版不把 `identity_score` 展示为百分比，避免用户误解为统计学概率；只展示分组和理由。

研究方向筛选优先使用候选数据已经提供的主题名称；如果后端没有主题名称，则隐藏该筛选，不使用 topic id 直接展示。

## 排序规则

推荐匹配排序采用稳定的多级排序：

1. 身份分组：`high` > `medium` > `review`；
2. `identity_score` 降序；
3. 有 ORCID 优先；
4. 证据条数降序；
5. 保持后端原始顺序作为最终稳定排序。

其他排序由用户主动选择：

- 论文数降序；
- 引用数降序；
- h-index 降序；
- 最近发表年份降序。

用户切换排序后，身份分组仍保留，避免“高引用但低身份可信度”的候选压过高置信度候选。

## 前端组件设计

将当前 `CandidateList` 拆为三个职责：

- `CandidateToolbar`：分组、筛选、排序和结果数量；
- `CandidateGroup`：按身份分组渲染；
- `CandidateCard`：显示候选信息、推荐理由和确认按钮。

筛选和排序状态只保存在候选结果页的 React state 中，不写入 URL 或数据库。重新搜索时重置为“全部 + 推荐匹配”。

## 错误和边界情况

- 候选没有机构、ORCID 或研究方向时，展示明确的“未公开/暂无数据”，不降低身份分组到错误状态。
- 过滤后没有结果时，显示清除筛选按钮和原始候选人数。
- 候选数量为 0 或 1 时不显示复杂筛选栏。
- 研究方向数据缺失时不显示研究方向筛选。
- 后端字段缺失时前端使用旧字段兼容渲染，保证旧缓存仍可打开。

## 测试计划

### 后端

- 分组规则覆盖高、中、低、独立档案和 ORCID 情况；
- 排序规则在同分时保持稳定；
- 推荐理由与实际证据字段一致；
- 旧缓存候选缺少新增字段时仍能正常返回。

### 前端

- 默认推荐排序；
- 分组筛选、机构关键词、ORCID 筛选；
- 论文数/引用数/h-index/最近发表年份排序；
- 筛选无结果和清除筛选；
- 中英文文案和移动端布局。

## 非本次范围

- 不重写身份消歧算法；
- 不新增机构官网、ORCID 或其他外部数据源；
- 不改变候选确认后的画像工作流；
- 不把候选人的学术影响力合并进身份匹配分数。
